# Auditoría funcional de IDsanna — 2026-09-15

## Resumen

La aplicación tiene cinco interfaces navegables en `index.html`: Inicio, Suite, Chat, Perfil y Acceso. La navegación DOM funciona, pero la experiencia completa todavía no está operativa porque `app/src/main/assets/config.json` mantiene vacíos `supabaseUrl` y `supabasePublishableKey` deliberadamente.

## Evaluación

| Interfaz | Estado | Capacidades reales | Faltantes críticos |
|---|---|---|---|
| Inicio | Parcial | Navegación, tarjeta Freemium 1000 créditos, resumen visual y feed placeholder | No consulta materias, créditos, actividad, recomendaciones ni estado remoto |
| Suite | Parcial funcional | Formulario de materia; inserta en `subjects` con sesión y RLS | No carga/lista/edita materias; no crea automáticamente agentes, esquema de metadatos, conversación ni espacio de estudio |
| Chat | Parcial | Selección visual de 8 agentes; invoca `chat-orchestrator` | No muestra respuesta, citas, errores detallados ni historial; `subject_id` depende de query string y puede ser nulo |
| Perfil | No funcional | Panel visual de perfil/progreso/créditos | No consulta Auth, `profiles`, saldos, ledger, learning events, evaluaciones ni recomendaciones |
| Acceso | Parcial | Login REST contra Supabase Auth; no guarda contraseñas | Registro no conectado, recuperación, cierre de sesión, refresco/persistencia segura de sesión y estado de usuario |

## Backend

- Migraciones presentes: 0001 a 0008.
- Esquema de metadatos ampliado con campos, reglas, tags, vistas, workflows, versiones y eventos.
- RLS configurado en las tablas nuevas.
- Ocho funciones de producto en el repositorio más `_shared`.
- El panel remoto verificado previamente mostraba desplegadas solo `consume-credits`, `process-document` y `rag-retrieve`; el resto requiere confirmar el workflow de despliegue.
- El workflow `.github/workflows/supabase-deploy.yml` exige los Secrets `SUPABASE_ACCESS_TOKEN` y `SUPABASE_PROJECT_REF`.

## Android y accesibilidad

- Shell WebView local con JavaScript, DOM Storage, Safe Browsing y selector de archivos.
- El servicio de accesibilidad queda limitado a navegadores permitidos.
- Puede recibir eventos de ventanas, contenido y vistas interactivas.
- No ejecuta pulsaciones autónomas: falta implementar el protocolo de acción confirmada, allowlist de dominios, botón de detención y auditoría de cada acción.

## Riesgos/errores encontrados

1. La configuración pública está vacía: correcto desde seguridad, pero bloquea toda operación real hasta colocar URL y publishable key legítimas.
2. La interfaz declara capacidades que todavía son placeholders.
3. La respuesta del chat se descarta después de invocar la función.
4. No existe sincronización de sesión con la UI.
5. No hay carga documental conectada desde las cinco interfaces.
6. El sistema de metadatos existe en base de datos, pero la interfaz todavía no lo consume para generar componentes.
7. No se debe declarar Mini-RAG end-to-end hasta probar Auth, materias, conversación, créditos, proveedor IA, ingesta, embeddings, retrieval, citas y persistencia.

## Veredicto

**Arquitectura preparada: sí. Aplicación funcional completa: no verificada.**

Prioridad de implementación:

1. Configuración pública legítima y despliegue remoto confirmado.
2. Estado Auth persistente y cierre de sesión.
3. CRUD de materias y creación automática del entorno de estudio.
4. Renderizado de respuestas/citas del chat.
5. Perfil conectado a créditos, progreso y eventos.
6. Ingesta documental y retrieval real desde la UI.
7. Motor de UI dinámica basado en `metadata_schemas`.
8. Acciones browser-only con confirmación y auditoría.
